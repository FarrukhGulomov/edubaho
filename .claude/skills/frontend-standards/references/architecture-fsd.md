# Feature-Sliced Design — архитектура frontend-проектов

> Читай при задачах, затрагивающих структуру проекта, новые модули, размещение файлов или межслойные зависимости.

Источник методологии: [feature-sliced.design](https://feature-sliced.design/). Ниже — адаптация под наш стек (React, TanStack Query, Zustand, Redux Toolkit, styled-components).

## 1. Три уровня абстракции

### Layers (согласно скоупу влияния)

Порядок снизу вверх, каждый слой может импортировать только нижележащие:

```
shared     → переиспользуемый инфраструктурный код (UI-кит, libs, api-клиент)
entities   → бизнес-сущности (viewer, order, product, ...)
features   → части функциональности (auth-by-oauth, add-to-cart, ...)
pages      → страницы приложения (user-page, checkout-page, ...)
processes  → сквозные бизнес-процессы (payment, onboarding, ...)
app        → инициализация приложения (init, styles, providers, routing)
```

**Правило импортов:** слой не может импортировать код с того же слоя из другого слайса напрямую или с вышестоящего слоя. Нарушение — architecture violation, требует согласования, а не молчаливого исключения.

### Slices (согласно бизнес-домену)

Второй уровень — деление по бизнес-домену внутри слоя (`features/auth`, `features/cart`). Правила разбиения на слайсы зависят от конкретного проекта и не регламентируются жёстко методологией — но должны быть согласованы в рамках проекта и не меняться без причины в рамках отдельной задачи.

### Segments (согласно назначению в реализации)

Третий уровень — сегменты внутри слайса:

- `ui` — компоненты, виджеты, презентационная логика;
- `model` — бизнес-логика слайса (store, actions/effects, хуки, типы);
- `api` — взаимодействие с сервером (TanStack Query hooks, запросы);
- `lib` — вспомогательные функции слайса;
- `config` — конфигурация модуля/окружения.

Пример:

```
features/auth
  by-phone/
    ui/            # компоненты формы
    model/         # useAuthByPhone, схема валидации
    api/           # мутация логина через TanStack Query
    index.ts       # Public API слайса
  by-oauth/
    ...
```

## 2. Public API

Каждый слайс обязан иметь `index.ts`, который явно экспортирует то, что разрешено использовать снаружи. Импорт из внутренних файлов слайса, минуя `index.ts`, запрещён.

```ts
// features/auth/by-phone/index.ts
export { LoginByPhoneForm } from './ui/LoginByPhoneForm';
export { useAuthByPhone } from './model/useAuthByPhone';
```

```ts
// правильно
import { LoginByPhoneForm } from 'features/auth/by-phone';

// неправильно — обход Public API
import { LoginByPhoneForm } from 'features/auth/by-phone/ui/LoginByPhoneForm';
```

## 3. Где живёт стек проекта

| Технология | Где используется |
|---|---|
| React | `ui`-сегмент любого слоя |
| TanStack Query | `api`-сегмент слайса — серверное состояние, кэш, инвалидация |
| Zustand | `model`-сегмент — локальное/фичевое клиентское состояние |
| Redux Toolkit | `app`/`processes` — сквозное состояние приложения, если проект уже строится на RTK |
| styled-components | `ui`-сегмент, максимально рядом с компонентом |

### Управление состоянием — что использовать

| Тип состояния | Инструмент | Где живёт (FSD) |
|---|---|---|
| Данные с сервера, кэш, рефетч, синхронизация | **TanStack Query** | `api`-сегмент слайса |
| Локальное/фичевое клиентское состояние (UI-стейт, форма, модалка) | **Zustand** | `model`-сегмент слайса |
| Сложное сквозное состояние приложения (если проект уже на RTK) | **Redux Toolkit** | `app`/`processes` |

Правила:

- Серверные данные не дублировать вручную в Zustand/Redux — источник истины для них TanStack Query.
- Не заводить новый стейт-менеджер под задачу, если для этого типа состояния уже есть выбранный инструмент в проекте.
- Смена стейт-менеджера в проекте — архитектурное решение, требует согласования, не делается «по пути» в рамках фичи.

## 4. Модульная альтернатива (для короткоживущих проектов)

Если проект не предполагает долгосрочного развития, допустима более простая модульная архитектура (DDD-подобная), где у каждого модуля есть свои слои с теми же ограничениями (нельзя обращаться к слою ниже напрямую, только через Public API модуля — `index.ts`).

```
modules/
  file/
    domain/
    ui/
    index.ts   # export * from './domain'; export * from './ui';
```

`libs/` в модульном подходе — кросс-проектные утилиты без привязки к бизнес-логике или инфраструктуре текущего проекта (код, который можно скопировать в другой проект без изменений).

**Выбор архитектуры (FSD vs модульная) фиксируется на старте проекта и не меняется в рамках отдельной задачи.**

## 5. Антипаттерны

| Антипаттерн | Что делать вместо |
|---|---|
| Импорт в обход `index.ts` слайса | Экспортировать нужное через Public API |
| Слой импортирует вышестоящий слой | Пересмотреть, где должна жить логика |
| Один слайс на весь домен без сегментов | Разбить на `ui/model/api/lib` |
| Business-логика в `ui`-сегменте | Вынести в `model` |
| Смешение серверного и клиентского состояния в одном сторе | Разделить: TanStack Query — сервер, Zustand/RTK — клиент |
| Новая архитектура/слой без согласования | Согласование с командой + фиксация решения |
